# Life RPG Web MVP

## MVP 定位

网页 MVP 的目标是证明一个完整命题：用户每天打开 Life RPG 后，能够通过一个轻量但有仪式感的循环，把现实任务转化为冒险行动，把完成结果转化为成长反馈，并把一天保存进自己的长期故事。

第一阶段不追求功能数量，而追求每日闭环的清晰度、稳定性和情绪价值。

## 新用户开局创建角色

新用户注册后的第一体验应是“开局创建角色”，而不是普通资料表单。体验可以借鉴 `Skyrim`、`Mount & Blade` 这类 RPG 开头：用户在现实世界的某个节点醒来，系统像记录员一样确认他的现实锚点、出身背景、内在倾向和第一章主线。

这一流程的产品目标是让用户感觉“我正在开始一段属于自己的冒险”，同时采集后续任务推荐、角色成长和每日循环所需的基础信息。

### 现实锚点

现实锚点用于把游戏叙事连接回真实生活：

- 昵称：用户在系统中的冒险者称号。
- 出生日期：用于生日仪式、年度回顾、年龄阶段感和星座推导。
- 星座：作为轻叙事标签和仪式感，不作为强能力判定。
- MBTI：作为自我理解入口，不当作科学结论或强规则。
- 学历：作为学习经历和任务建议的参考，不用来评价用户价值。
- 身高、体重：作为可选健康档案，只服务健康主线、体能记录和长期变化回顾。
- 人生阶段和现实职业：用于初始属性、职业推荐和任务建议。
- 当前困境和想成为的人：用于生成第一章主线和长期成长叙事。

MBTI、星座、出生日期、学历和身体数据应该被表达为“记录员确认现实锚点”，而不是“系统给用户贴标签”。它们可以影响文案、仪式和轻量偏好，但不应决定过多核心数值。身高体重必须可跳过，界面文案要避免评价、羞辱或制造身体焦虑。

### 开局流程

推荐流程：

1. 序章：现实锚点
  输入冒险者称号、出生日期、人生阶段、现实职业、学历、MBTI，并自动推导星座。
2. 第二幕：出身与节律
  选择高能量时段、完成重要任务的偏好，并可选记录身高体重，生成初始种族/背景特性。
3. 第三幕：第一章主线
  选择当前最想改变的方向，写下当前困境和想成为的人。
4. 角色确认
  系统生成主副职业、初始画像、匹配度、第一章主线摘要，允许用户接受推荐或手动调整。

完成后进入首页或晨间加载。后续可以把这张冒险者档案作为长期成长页面的一部分，让用户在数月后回看“第一章从哪里开始”。

## 每日核心循环

### 1. 晨间加载

用户每天第一次进入系统时，先完成“今天进入游戏”的仪式：

- 确认今日状态：能量、节律、昨天是否完成夜间存档。
- 生成今日氛围：运势、种族/节律加成、温和提醒。
- 引导用户选择今日主线，而不是直接掉进任务列表。

现有基础：`src/app/morning-load/page.tsx` 已有晨间加载、今日运势、种族特性和昨日封存提醒；`src/app/page.tsx` 已通过 `lastMorningLoad` 判断是否进入过晨间仪式。

MVP 打磨重点：晨间页结束后应明确进入“选择今日任务”的下一步，并把今日主线写入稳定数据源。

### 2. 任务选择

用户把现实行动转化成今日任务：

- 主线任务：今天最重要的一件事。
- 支线任务：有价值但不是今日胜负手的行动。
- 日常任务：生活维护、健康、学习、整理等小行动。

现有基础：`src/app/tasks/page.tsx` 已支持任务创建、职业、难度、奖励、专注模式和事后记录模式；`supabase/schema.sql` 中已有 `tasks` 表。

MVP 打磨重点：降低任务创建复杂度，让用户先选“今天要推进什么”，再进入难度和模式细节。事后记录应作为低摩擦入口保留，但每日次数和奖励折扣需要清楚解释。

### 3. 专注执行

用户进入现实副本，系统用倒计时、战斗叙事和视觉反馈帮助用户保持沉浸：

- 专注模式适合需要开始前承诺的任务。
- 事后记录适合已经完成但需要保存成果的任务。
- 失败、提前完成、昏迷和撤退都应被写成叙事事件，而不是单纯惩罚。

现有基础：`src/app/focus/page.tsx` 提供沉浸背景；`src/app/tasks/page.tsx`、`src/components/task-explore-overlay.tsx`、`src/lib/task-adventure-flow.ts` 和 `src/lib/adventure-system.ts` 已形成任务冒险流程。

MVP 打磨重点：统一“任务页内探索”和独立 `focus` 页的职责。第一阶段可以让任务页承担完整执行和结算，`focus` 页作为视觉增强后置打磨。

### 4. 即时奖励

完成任务后，用户立即得到可理解、可追溯的反馈：

- 角色 XP 与等级进度。
- 晶石奖励。
- 职业/技能树进度。
- 掉落、徽章或收藏解锁。
- 冒险战报与最近完成记录。

现有基础：`src/lib/execute-task-completion.ts` 负责任务完成结算；`src/lib/task-rewards.ts` 负责奖励计算；`src/lib/skill-tree.ts`、`src/lib/gear-inventory.ts`、`src/lib/cosmetics.ts` 已有成长和掉落逻辑。

MVP 打磨重点：奖励弹层或完成反馈需要讲清楚“为什么得到这些奖励”，并把结果稳定写入任务、奖励流水、技能进度和日志。

### 5. 夜间存档

一天结束时，用户把今天保存成故事：

- 汇总今日完成、奖励、战报和里程碑。
- 提供低压力复盘：感谢、困难、明日伏笔。
- 生成今日封存结果和连续存档状态。
- 明确允许“今天休息也可以封存”。

现有基础：`src/app/night-save/page.tsx` 已有篝火封存、证书和返回任务入口；`src/lib/night-seal.ts` 和 `src/lib/daily-log.ts` 已有日记、封存、周报与里程碑逻辑。

MVP 打磨重点：夜间存档应成为每日循环的结束点，而不是可有可无的装饰。封存结果需要进入 Supabase 的每日日志表，localStorage 只保留临时草稿和 UI 状态。

### 6. 长期成长

系统把多天行动累积为“我正在成为什么样的人”：

- 职业倾向与技能树。
- 长期史诗任务和周常挑战。
- 成就、收藏和装备。
- 人生数据、趋势和故事索引。

现有基础：`src/app/skills/page.tsx`、`src/app/profession/page.tsx`、`src/app/epic-quests/page.tsx`、`src/app/weekly/page.tsx`、`src/app/stats/page.tsx`、`src/app/adventure-log/page.tsx` 已有长期成长雏形。

MVP 打磨重点：长期成长页面应从“功能集合”收束为“成长证据”。优先展示与每日闭环直接相关的 XP、技能、日志、任务趋势和关键里程碑。

## Web MVP 实现批次

> **图例**：`[x]` 已实现；`[ ]` 未做或仅部分；`[~]` 部分满足（见括注）。

### Batch 1: 打通每日闭环

**状态：基本完成**（跨设备以「任务 + 档案 XP/晶石 + 今日主线缓存 + 封存日日志 + 奖励流水」为主；晨间/封存 **UI 提示键** 仍可能仅存本机，见验收 3。）

目标：用户可以从晨间加载开始，创建/选择今日任务，完成一次专注或事后记录，获得奖励，并在夜间封存成日志。

范围：

- 首页改造成每日指挥中心：显示今日状态、今日主线、下一步行动、夜间封存入口。（`src/app/page.tsx` + `src/lib/daily-loop-state.ts` / `daily-loop-events.ts`）
- 晨间加载增加今日主线选择或跳转任务选择的明确入口；支持晨间已完成后 `**/morning-load?pickMain=1`** 仅补选主线。（`morning-load/page.tsx`）
- 任务页收敛创建流程，优先支持一个主线任务和若干支线/日常任务。（`task_track` + 创建前三档 + `?mode=quick` 默认主线）
- 完成结算统一写入任务完成、XP、晶石、**奖励流水** `reward_events`、最近完成。（`execute-task-completion.ts`）
- 夜间封存写入 **Supabase `daily_logs`**（与本地 IndexedDB 并存）；本地生成每日日志与封存记录不变。（`night-save` + `batch1-supabase-sync.ts`）
- 今日主线 / 推进等写入 `**profiles.day_loop_cache**` 并首页/任务页水合，减轻换设备丢主线。（`batch1-supabase-sync.ts`）

验收：

- [~] 新用户完成 onboarding 后能顺畅进入首页和晨间仪式。（依赖现有 `onboarding` 与路由；未做专项 E2E 报告）
- 老用户每天至少能完成一次「晨间 → 任务 → 奖励 → 夜间」的完整循环。（产品路径已通；仍依赖用户实际使用）
- [~] 刷新页面或换设备后，核心进度不丢失。（**已上云**：`tasks`、`profiles`（xp/crystals）、`reward_events`、`daily_logs`（封存日）、`day_loop_cache`（今日主线等）；**仍以本机为主或未迁移**：完整 `userProfile`/虚拟角色、IndexedDB 主日志、晨间 `lastMorningLoad` 等 UI hint）

**依赖**：在 Supabase 执行 `supabase/schema.sql` 中 Batch 1 相关增量（`reward_events`、`daily_logs`、`task_track`、`day_loop_cache` 及 RLS）。

### Batch 2: 强化成长与记录

**状态：已完成**（技能解释、日志整合与云端封存合并、统计收敛与叙事、侧栏轻量入口；技能树 **数据源** 仍以本地 `userProfile` 为主，上云属后续迁移。）

目标：把多天行动沉淀成可解释的成长证据。

范围：

- 技能进度从任务完成中稳定累积（既有逻辑），展示**最近解锁**与**下一节点**文案与进度条。（`skill-tree.ts`：`skillTreeNextStep`、`explainLastSkillUnlock`；`skills/page.tsx`）
- 日志页整合夜间封存摘录、冒险时间轴、手动里程碑；**合并** Supabase 已封存 `daily_logs` 与本地日志。（`journal/page.tsx` + `daily-logs-merge.ts`）
- 统计页优先本周叙事、热力、职业分布、等级趋势、晶石与战力曲线；次要指标收入 `**<details>`**。（`stats/page.tsx` + `growth-narrative.ts`）
- 史诗任务和周常只保留轻量入口（侧栏「更多」小字链）。（`sidebar.tsx`）

验收：

- 用户能解释「我这周为什么升级/解锁了某个技能」。（技能页「成长证据」+ 统计预测区 + 数据页链到日志）
- 夜间封存不只是图片或证书，而能成为可回看的生活记录。（`daily_logs` + 日志页「夜间封存摘录」+ 合并列表）
- 低能量日、失败任务和重新开始都有温和叙事。（`growth-narrative.ts`：日志空状态、统计顶部叙事）

### Batch 3: 整理视觉和导航

**状态：已完成**（侧栏按「今日 / 任务 / 记录 / 成长 / 奖励·收藏 + 更多」分组；`globals.css` 定义全站 `.card` 与 `.mvp-page-title` / `.mvp-page-desc`；任务、日志、统计、技能、职业、商店、背包、收藏、战报等页统一 `MvpPageHeader`。）

目标：让产品像一个统一系统，而不是功能 demo 集合。

范围：

- 主导航按每日循环组织：今日、任务、记录、成长、奖励/收藏。（`src/components/sidebar.tsx`）
- 统一核心卡片与页面标题层级（`.card`、`.mvp-page-title` / `.mvp-page-desc`、`MvpPageHeader`）；奖励弹层与空状态文案仍以既有实现为主，未做全量替换。
- 将后置功能降权：商店、背包、独立冒险、收藏、周常不抢首页主路径。（奖励组侧栏弱对比链 + 「更多」收纳实验玩法）
- 保留视觉仪式感，但减少与完成现实行动无关的干扰。（夜间封存等仪式页保留独立视觉，仅标题层级对齐）

验收：

- 用户不用理解所有 RPG 系统，也能知道今天该点哪里。（侧栏分组 + 指挥室晨间优先）
- MVP 核心页面视觉语言一致。（卡片与页头组件化）
- 后置玩法存在但不打断每日闭环。（更多区 + 非主导色链）
